# Code map

Every Go package in the repo with the first sentence of its doc comment. Generated by `make codemap`; edit the
package's `// Package ...` comment, never this file. `go doc ./<path>` prints the full comment.

- `board` - Package board renders the read-only captain board (ADR 0011): one self-contained HTML page with its CSS and JS inlined and the current snapshot embedded, so it opens with no network and loads no external resource.
- `cmd/cox` - Command cox is the coxswain CLI.
- `hooks` - Package hooks embeds leader.json, the one source of the leader hook group shapes (events, matchers, timeouts, async).
- `internal/adapter/backend` - Package backend defines the one Backend interface the coxswain core talks to (decision 0002).
- `internal/adapter/backend/fake` - Package fake is an in-memory Backend for tests.
- `internal/adapter/backend/herdr` - Package herdr is the optional Backend adapter (decision 0002), completed to full capability in M10 (ADR 0012).
- `internal/adapter/backend/orca` - Package orca is the default Backend adapter (decision 0002).
- `internal/adapter/forge` - Package forge is the adapter seam to a code forge (GitHub).
- `internal/adapter/forge/fake` - Package fake is a Forge that replays a fixture for tests.
- `internal/adapter/forge/github` - Package github is the Forge adapter over the gh CLI.
- `internal/adapter/harness` - Package harness is the model-agnostic seam between the core and whatever runs an agent (Claude Code, Codex, ...).
- `internal/adapter/harness/claude` - Package claude is the Claude Code harness adapter: wake push via hooks, automatic checkpoints via PreCompact and SessionStart shims, and telemetry read from the session log.
- `internal/adapter/harness/codex` - Package codex is the Codex harness adapter: no hooks, so wake is pull (the leader drains each turn and blocks on `cox wake wait` when idle), checkpoints are manual (the worker writes them at phase boundaries), and telemetry is unknown.
- `internal/adapter/harness/fake` - Package fake is a configurable harness.Harness for tests.
- `internal/adapter/harness/pi` - Package pi is the Pi (@earendil-works/pi-coding-agent) harness adapter.
- `internal/adapter/harness/registry` - Package registry maps a harness name to its adapter and enforces the capability card at dispatch time.
- `internal/adapter/review/lavish` - Package lavish is the optional review-surface adapter (M13, ADR 0008): it wraps the external lavish-axi CLI so a generated artifact (internal/artifact) can be opened in a browser and the reviewer's feedback recorded.
- `internal/adapter/service` - Package service is the adapter that runs a project's service script (&lt;ws&gt;/cox/services/&lt;alias&gt;.sh) with the four verbs preflight | start | health | stop.
- `internal/arena` - Package arena orchestrates one arena round: trigger from policy, build the blinded context pack, resolve each role's harness, render a story per role, and dispatch each on its own read-only worktree.
- `internal/arena/check` - Package check machine-verifies an arena role's claim report.
- `internal/arena/cite` - Package cite verifies source citations against git.
- `internal/arena/pack` - Package pack builds the shared, verified, blinded context pack an arena hands every role.
- `internal/arena/report` - Package report parses an arena role's claim report into a structured form both `arena check` (validation) and `synth` (synthesis) read.
- `internal/arena/roles` - Package roles decides an arena's shape from policy: the trigger level (full/lite/none), which roles run, the harness each role uses (never hard-coded - the adversary is "not-leader", the reviewer is "same-as-leader"), and the story file each role is dispatched as.
- `internal/arena/synth` - Package synth assembles the per-role claim reports into one synthesis skeleton the leader fills with verdicts.
- `internal/arena/verify` - Package verify runs the `check` an arena role attached to an epic-blocking or significant claim (ADR 0013) and records pass, fail, or unknown.
- `internal/artifact` - Package artifact is the coxswain.artifact.v1 contract (M13, ADR 0008/0013): a review page under &lt;epic&gt;/reports/visual/&lt;name&gt;.html carries a sidecar &lt;name&gt;.artifact.json naming its kind, its sources with content shas, when it was generated, and whether cox or the leader generated it.
- `internal/baseline` - Package baseline replays a story from the repository state that existed BEFORE its solution, so a harness's unassisted performance can be measured without the answer leaking through git history.
- `internal/bearings` - Package bearings is the leader's session start: one ordered digest composed from cox's sources of truth (the leader lease, internal/doctor, the wake queue, the story event log, questions/, BACKLOG.md) plus the three budgeted memory files under cox/notes/ and their curation pass.
- `internal/boundexec` - Package boundexec is cox's one bounded external exec (firstmate bin/fm-timeout-lib.sh fm_exec_timed, ac2ed3b): a command runs in its own process group, the whole group gets TERM at the bound and KILL after a short grace, a descendant holding captured output cannot keep the caller waiting, and a TERM/INT/HUP to cox reaches every live bounded command before cox ends.
- `internal/doctor` - Package doctor inventories every coxswain installation on this machine and the control directory of every epic under each, so a fix can be shown to reach the intended clone (F09).
- `internal/env` - Package env owns a story's environment: it generates the env file completely, validates it, and publishes it atomically (tmp + rename, F13); it records port/db/sim ownership in .cox/resources.json and clears ownership only after an external delete is confirmed (F03/F04).
- `internal/epic` - Package epic creates, renders stories for, and closes an epic.
- `internal/identity` - Package identity binds a worker to a story by attempt id and canonical worktree path, never by path prefix or directory name (F07).
- `internal/lab` - Package lab defines and reports self-improvement experiments that turn a policy rule on or off and compare a scorecard metric across the two variants.
- `internal/migrate` - Package migrate converts a v1 epic control file (&lt;epic&gt;/.run, append-only "key=value", last value wins) into the v2 control tree: an events.jsonl the fold can replay, .cox/sessions/&lt;story&gt;.json for each live dispatch, and .cox/run.
- `internal/protocol/brief` - Package brief is the brief channel: the context pack a leader sends a worker alongside the story.
- `internal/protocol/busy` - Package busy is the harness-owned busy-state record: idle/busy is a fact the HARNESS reports (captain ruling 2026-09-21, wave 3), never something a backend infers from a UI.
- `internal/protocol/checkpoint` - Package checkpoint is what a worker leaves for its own future self so a restart or compaction is a non-event (coxswain.checkpoint.v1).
- `internal/protocol/control` - Package control is the control channel: the verb-allowlisted operations a leader runs against a worker (interrupt | park | relaunch).
- `internal/protocol/decision` - Package decision ports firstmate's status-line grammar and keyed decision fold (bin/fm-classify-lib.sh, pinned a8572f6) so every cox reader of a worker status line agrees on one statement of the rules.
- `internal/protocol/inbox` - Package inbox is the steer channel (coxswain.inbox.v1): durable leader instructions to a running worker under &lt;epic&gt;/inbox/&lt;story&gt;/NNN.msg.
- `internal/protocol/question` - Package question is the file-based question/reply channel for the terminal plane (ADR 0012, arena round 1): a worker allocates a durable question id under &lt;epic&gt;/questions/&lt;story&gt;/qNNN.md, the leader writes qNNN.answer.md, and the worker polls for the answer and moves the pair into handled/.
- `internal/protocol/report` - Package report is the worker-&gt;leader report channel shared by every backend (ADR 0012): a worker writes its progress, completion, blocker, or question straight into the epic directory instead of through a backend mailbox.
- `internal/protocol/status` - Package status is the worker-&gt;leader status channel.
- `internal/quota` - Package quota is the coxswain.quota.v1 contract: the only quota type routing, the watcher, cox state, and the board read (Option C, m11-quota-routing DESIGN.md).
- `internal/reconcile` - Package reconcile finishes stories left in pending_external by a crash between the two appends of a side effect.
- `internal/routing` - Package routing chooses the harness (and model) for a story.
- `internal/scorecard` - Package scorecard reports effectiveness metrics per dispatch attempt, from data already on disk.
- `internal/state` - Package state is the source of truth for story lifecycle: an append-only event log (coxswain.event.v1), a pure fold to a snapshot, and the resolver that merges the five observation sources into a fleet view (coxswain.fleet.v1).
- `internal/supervision` - Package supervision is the supervision-need registry, ported from firstmate bin/fm-supervision-lib.sh fm_supervision_status, bin/fm-check-register.sh, bin/fm-check-unregister.sh and bin/fm-check-lib.sh (pinned a8572f6).
- `internal/verdict` - Package verdict computes the three-state results (pass | fail | unknown) for a story PR audit and an epic ship readiness check.
- `internal/version` - Package version holds the coxswain build version.
- `internal/wake` - Package wake is the generation-stamped wake queue (coxswain.wake.v1) the zero-token watcher uses to hand work to the leader without polling.
- `internal/watch` - Package watch is the zero-token watcher: it reads the backend mailbox without consuming it, classifies new mail into the wake queue, runs the inbox re-ring ladder, and probes silent workers, all without typing into any terminal or spending a leader turn.
- `internal/workspace` - Package workspace loads the two enterprise registry files a leader resolves against: cox/workspace.json (projects, repos, services, hosts) and cox/policy.json (topology, waves, context thresholds, harness options, arena trigger, delivery style).
- `internal/worktree` - Package worktree creates a verified isolated checkout for a story and never falls back.
- `skills` - Package skills embeds the pinned Coxswain leader skills so `cox workspace init` can drop them under &lt;ws&gt;/.agents/skills/, giving both a Claude and a Codex leader the same skill set with no separate download.
- `templates` - Package templates embeds the coxswain file templates (workspace/policy scaffolds, epic DESIGN.md, story.md, the service adapter example) so the cox binary carries them with no runtime file lookup.
